## 1. 会前准备

全组同一时刻仅运行一份 Tracker。打洞演示时服务位于王的桥接机。中继回放允许使用录像。

**王（打洞环境）**

```bash
cd ~/CS374
ip -4 addr show | grep inet
./room_server
./relay_server
```

地址须为 `172.20.10.x` 网段。将当前 IPv4 发给房主（下文 `TRACKER`）。地址随入网变化，程序无需重编译。

**刘（房主）** — 本机不启动 `room_server`。

```bash
cd /mnt/d/Coding_Project/CS374/Project
make && make transfer
./client_transfer --host --session session_1e22ca8e --room TRACKER --nick 房主 --mode udp
```

案情板：`join 房主 TRACKER host`，随后 `probe`。房主本步不执行 `get`。

**侦探（王或彭，空缓存目录）**

```bash
./client_transfer --room TRACKER --nick 侦探 --data-dir .cache/demo_punch --mode udp
```

`join 侦探 TRACKER` → `probe` → 确认反射非 `-:0` → `get`。

房间满员返回 `0x0005` 时该窗 `quit`。`TRACKER_OFFLINE` 表示服务未启动或地址填写错误，同一窗口再次 `join`。

## 3. 实验 9（约 2.5 分钟）

先讲中继，再讲打洞，使路径对照清楚。

**2026-10-28 中继回落（场景 3）**

- Tracker 位于刘 WSL，`portproxy` 转发 TCP 37401、37405。  
- 全员反射 `-:0`，`--mode udp` 仍走路径「中继」。  
- 四人群 `get` 后三文件已有。证据：[`实验记录.md`](实验记录.md) 实验 9。  
- 失败走中继符合 RFC 5128，属于设计回落。

**2026-10-29 打洞（场景 2/4）**

- 王桥接 `ens33` = `172.20.10.6`，本机监听 UDP 37402。  
- 刘房主反射 `172.20.10.2:50181`；王空缓存 `get` 后顶栏路径「打洞」。  
- `TRANSFER_STATS`：`relay_up=0`，`from_1=171568`。  
- 探测、打洞、子包共用同一 UDP 文件描述符。旧缓存会使路径停在「未知」、来源为 local，须使用空目录重拉。

现场打洞环境不可用时，播放 2026-10-29 录像并标明录像，定格路径栏。

## 4. 分人讲解要点

**刘：** 通告范围限于本网、不跨路由；路径栏三种文案；实验 4：进程重启后能够绑定，原因是 `SO_REUSEADDR`；控制时长。  
**彭：** 粘包与半包；`get` 经唤醒管道通知 `select`；子包重试与有界次数后改中继。  
**王：** Tracker 与中继同机；迭代 `--iterative` 阻塞第二连接；当场通报当前 IP。  
**陈：** 种子不下发；两局 hash 不同；实验 8 公式与失败情形。

## 5. 稳定现场三项

1. 三端残页不同 → `get` → 多源（板上「来源」并非全部为房主）。  
2. 关闭 `room_server` 后房主仍 `announce`，未 `join` 的 D 窗可见通告。  
3. 顶栏显示「本网直连」「打洞」「中继」之一。场景 1 本网直连四人群已列为范围外，现场不承诺该项。

`next` / `answer` / `choose` 在陈侧书面约定真校验之前，演示说明为流程占位；证物齐全后推进章节。
