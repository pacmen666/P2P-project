# 碎片档案　应用层协议 v1 格式约定

四人确认后方可分头编写。变更须升 `ver`，不得私下改字段宽度。  
种子不得出现在本约定的任何字段、日志对外列或界面控件中。

**起草：** 彭（收发、读状态机、连接种类）　王（进房、对外地址、中继）　陈（摘要与分块编号）　刘（界面状态、通告、打洞客户端）  
**确认：** 陈　　彭　　王　　刘　　日期：________

## 1. 公共头部（所有 TCP / UDP 报文）

长度固定 **8 字节**。多字节整数均为**网络字节序**（发送前 `htons`/`htonl`，接收后 `ntohs`/`ntohl`）。

| 偏移 | 长度 | 名称 | 取值 |
|------|------|------|------|
| 0 | 2 | `magic` | `0x4641`（ASCII `'F''A'`） |
| 2 | 1 | `ver` | `1` |
| 3 | 1 | `cmd` | 见第 3 节 |
| 4 | 2 | `req_id` | 请求方在 1–65535 循环取值；对端应答必须原样带回。无请求对应的通知填 `0` |
| 6 | 2 | `body_len` | 正文长度，**不含**这 8 字节。合法范围 0–65535 |

TCP 上一条报文 = 8 字节头 + `body_len` 字节正文。  
UDP 上一个数据报 = 恰好一条报文，且 **8 + `body_len` ≤ 1200**。超出则视为非法，丢弃。

`magic` 或 `ver` 不符：丢弃该报文；若在 TCP 上出现，关闭该连接。

|------|------|------|--------|------------|
| 房间服务监听 | TCP | **37401** | 王 | `SO_REUSEADDR`，便于关闭后立即再绑 |
| 房间服务探测 | UDP | **37402** | 王 | 用 `recvfrom` 登记源地址；应答仍 `sendto` 该地址 |
| 中继服务 | TCP | **37405** | 王 | 与房间服务同机；`SO_REUSEADDR` |
| 客户端 TCP 互传监听 | TCP | 绑定 `0`，进房时上报 | 彭 | 每端一个；名单里公布。**必须** `SO_KEEPALIVE`。另：未完成的 `PIECE_REQ` 应用层等待超过 **5 秒**无任何应答，即视该对端失效并换源。房间服务关闭后，玩家 TCP 上每 5 秒互发 `HEARTBEAT`，15 秒无应答视为离线。不得只依赖系统默认保活空闲时间（常达数小时） |

| 局域网通告 | UDP | **37404** | 刘 | `SO_BROADCAST`；本机多实例才用 `SO_REUSEPORT` |

房间服务配置允许主机名，解析后再连 37401（实验 5）。  
IPv4 only。地址在正文中以 4 字节网络序出现，端口 2 字节网络序。

## 3. 指令码

| `cmd` | 名称 | 承载 | `req_id` | 正文概要 | 负责 |
|-------|------|------|----------|----------|------|
| 0x01 | `JOIN_REQ` | TCP→房间 | 有 | 进房 | 王 |
| 0x02 | `JOIN_OK` | TCP←房间 | 回带 | 自己的 `peer_id`、名单 | 王 |
| 0x03 | `JOIN_ERR` | TCP←房间 | 回带 | 错误码 | 王 |
| 0x04 | `HEARTBEAT` | TCP↔房间；房间关闭后亦用于玩家 TCP | 0 | 可空 | 王定格式，彭在玩家连接上复用 |
| 0x05 | `HEARTBEAT_ACK` | TCP↔房间；房间关闭后亦用于玩家 TCP | 0 | 可空 | 王定格式，彭复用 |
| 0x06 | `PEER_LIST` | TCP←房间 | 0 或回带 | 全员地址（私网 + 反射） | 王 |
| 0x07 | `MANIFEST` | TCP 房主→房间及玩家 | 0 | 摘要清单，**无种子** | 陈定字段，彭发 |
| 0x08 | `BITFIELD` | TCP；打洞/中继路径上若尚未交换过则补发 | 0 | 某文件已持有位图 | 彭 |
| 0x09 | `HAVE` | TCP 玩家↔玩家 | 0 | 新完成的一块 | 彭 |
| 0x0A | `PIECE_REQ` | TCP 或 UDP | 有 | 要一块；UDP 带 `sub_mask` | 彭 |
| 0x0B | `PIECE_DATA` | TCP 或 UDP | 回带 | TCP：整块；UDP：一个子包 | 彭 |
| 0x0C | `PIECE_NAK` | TCP 或 UDP | 回带或 0 | 缺哪些子包 / 无此块 | 彭 |
| 0x0D | `PROBE` | UDP→房间 37402 | 0 | 登记反射地址 | 刘发，王收 |
| 0x0E | `PROBE_ACK` | UDP←房间 | 0 | 告诉你「我看见的地址」 | 王 |
| 0x0F | `PUNCH` | UDP 玩家↔玩家 | 0 | 打洞探测 | 刘 |
| 0x10 | `RELAY_BIND` | TCP→中继 | 有 | 声明自己的 `peer_id` | 王协议，刘/彭连 |
| 0x11 | `RELAY_WRAP` | TCP↔中继 | 0 | 内层仍是一条完整 v1 报文 | 王转发 |
| 0x12 | `ANNOUNCE` | UDP 广播 37404 | 0 | 房主通告 | 刘 |
| 0x13 | `ERROR` | 任意 | 回带或 0 | 通用错误 | 全员 |
| 0x14 | `ADDR_QUERY` | TCP→房间 | 有 | 索取最新反射地址 | 刘，王答 |
| 0x15 | `ADDR_REPLY` | TCP←房间 | 回带 | 对端反射地址 | 王 |
| 0x16 | `MANIFEST_REQ` | TCP→房间或房主 | 有 | 晚进房 / 重连索取清单 | 彭发，王缓存并答 |

未列出的 `cmd` 视为非法。房间服务必须缓存本局已收到的 `MANIFEST`。晚到节点在 `JOIN_OK` 之后若房间已有缓存，房间须**立即再发一条** `MANIFEST`，不必等请求。节点仍可用 `MANIFEST_REQ` 再要一次（断线重连）。

## 4. 编号与尺寸（陈）

| 量 | 约定 |
|----|------|
| `session_id` | 4 字节无符号。开局随机，**不是**种子。界面「局号」显示此值的十六进制 |
| `peer_id` | 1 房主，2–4 玩家。由房间服务在 `JOIN_OK` 分配 |
| `file_id` | 1、2 为第一章证物，3 为第二章证物 |
| 单文件 | ≤ 512 KiB |
| 逻辑分块 | **16384** 字节，末块可短。块号从 0 计 |
| 子包数据 | **1024** 字节，末子包可短。16 KiB 整块恰好 16 个子包 |
| 摘要 | SHA-256，32 字节原始值，线上不发十六进制文本 |
| 种子 | ≥ 16 字节密码学随机，仅房主进程内存；**无对应字段** |
| `seed_hash` | `SHA-256(种子)`，可放进清单作展示，不能用于重放生成器 |
| 昵称 | UTF-8，长度前缀，1–16 字节，不含 `0x00` |

块数：`piece_count = ceil(file_size / 16384)`。  
末块长度：`file_size - piece_index * 16384`。  
UDP 子包数：`sub_count = ceil(piece_len / 1024)`。

本地保存（陈，路径由实现自定，但不得把种子写入文件名或文件内容）：

- 成品：`session_<id>/file_<file_id>`
- 已完成块：同目录下按块落盘，重启后只保留摘要核对通过的块
- 清单：可另存 `manifest.bin`（与线上 `MANIFEST` 正文相同）

## 5. 各指令正文

下列偏移均相对正文起点。长度为「剩余」的字段以 `body_len` 截断。字符串均为「1 字节长度 + 字节」，不含结尾 `0`。

### 5.1 `JOIN_REQ`（王）

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 2 | `room_id`（0 表示创建并由服务分配） |
| 2 | 1 | `role`：1 房主，2 玩家 |
| 3 | 4 | 本机私网 IPv4（**不得**填 `0.0.0.0`。可在连上房间服务后 `getsockname` 取得） |
| 7 | 2 | 本机 TCP 互传监听端口 |
| 9 | 2 | 本机 UDP 打洞套接字端口（即探测所用那个） |
| 11 | 1 | `nick_len` |
| 12 | `nick_len` | 昵称 |

### 5.2 `JOIN_OK`（王）

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 2 | `room_id` |
| 2 | 1 | 自己的 `peer_id` |
| 3 | 1 | `peer_n`（含自己） |
| 4 起 | 重复 `peer_n` 次 | 见下表「成员项」 |

本条发完后，若房间已缓存 `MANIFEST`，同一 TCP 连接上必须紧接着再发一条 `MANIFEST`（`req_id = 0`）。

成员项：

| 相对 | 长度 | 名称 |
|------|------|------|
| 0 | 1 | `peer_id` |
| 1 | 4 | 私网 IPv4 |
| 5 | 2 | TCP 互传端口 |
| 7 | 2 | UDP 本地端口 |
| 9 | 4 | 反射 IPv4（未知填 0） |
| 13 | 2 | 反射 UDP 端口（未知填 0） |
| 15 | 1 | `nick_len` |
| 16 | `nick_len` | 昵称 |

`PEER_LIST`、`ADDR_REPLY` 的成员项与上表相同。`ADDR_QUERY` 正文仅 1 字节目标 `peer_id`。反射地址为全 0 时不得对其发起打洞，须等待后续 `PEER_LIST`。

本网 TCP 直连（彭，名单中的**客户端上报的私网 IPv4** + TCP 端口；不得把房间服务看见的 TCP 源地址当成宿舍网私网地址——房间若在公网，二者不是同一回事）：

- 套接字必须非阻塞。`connect` 后用 `select` 等写就绪，**超时 1.5 秒**。不得在网络线程里做阻塞 `connect`。
- 只由 **`peer_id` 较小的一方**向较大的一方发起 `connect`；较大方只 `accept`。若误出现两条连接，关掉由较大 id 发起的那条。
- 跳过 `peer_id` 等于自己的表项。若对端私网地址与端口与本机监听相同，视为环回自连，不得 `connect`。
- 握手成功后双方立刻交换 `BITFIELD`（含发送方 `peer_id`）。若收到的 `peer_id` 等于自己，立即关闭该连接。
- 1.5 秒未写就绪或 `SO_ERROR` 非 0：放弃该私网 TCP，改走打洞，不阻塞其他描述符。
- 同一对端已有可用的本网 TCP 时，不再向其发 UDP `PIECE_REQ`。

### 5.3 `JOIN_ERR` / `ERROR`

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 2 | `err`（见第 6 节） |

### 5.4 `MANIFEST`（陈定，彭发，房间须缓存）

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 4 | `session_id` |
| 4 | 32 | `seed_hash`（不是种子） |
| 36 | 1 | `file_n`（本项目为 3） |
| 37 起 | 重复 `file_n` 次 | 文件项 |

文件项：

| 相对 | 长度 | 名称 |
|------|------|------|
| 0 | 1 | `file_id` |
| 1 | 1 | `chapter`（1 或 2） |
| 2 | 1 | `kind`：1 图，2 文本 |
| 3 | 4 | `file_size` |
| 7 | 32 | 整文件 SHA-256 |
| 39 | 2 | `piece_count` |
| 41 起 | `piece_count × 32` | 各逻辑分块 SHA-256，块号升序 |

不得附加种子、生成器内部状态或明文答案字段。真凶只存在于文件正文中。

房主发出后，房间服务保存最近一份，供晚加入者使用。仅「转发一次、过后丢弃」不足以覆盖后进房与重连。无缓存时对 `MANIFEST_REQ` 回 `ERROR` `0x0011`。

### 5.5 `BITFIELD`（彭）

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 4 | `session_id` |
| 4 | 1 | 发送方 `peer_id` |
| 5 | 1 | `file_id` |
| 6 | 2 | `piece_count`（须与清单一致） |
| 8 | `ceil(piece_count/8)` | 位图。块 0 为第 1 字节的最高位 |

最后一个字节中、下标 ≥ `piece_count` 的填充位必须置 0。接收端解析时必须屏蔽这些位，不得凭「该字节非 0」推断对端持有不存在的块。

TCP 直连建立后，双方各发 3 份（三个 `file_id`），并核对应答中的 `peer_id`。打洞成功或中继就绪后，若这对端尚未交换过位图，经当前路径再发 3 份。此后持有变化只发 `HAVE`（TCP、已认证 UDP、中继各一份，以当时已接通路径为准）。房间服务关闭后，不得再向房间询问「谁有哪些块」。

### 5.6 `HAVE`（彭）

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 4 | `session_id` |
| 4 | 1 | `file_id` |
| 5 | 2 | `piece_index` |

本机该块摘要核对通过后，向**当前所有已接通**的玩家连接各发一次。

### 5.7 `PIECE_REQ`（彭）

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 4 | `session_id` |
| 4 | 1 | `file_id` |
| 5 | 2 | `piece_index` |
| 7 | 2 | `sub_mask` |

`sub_mask` 为 16 位子图，**最低位对应 `sub_index` 0**（主机序下用 `mask & (1u << k)`，发送前 `htons`）。`0xFFFF` 表示该逻辑块的全部子包。超出本块实际 `sub_count` 的位，发送端必须清零，接收端必须忽略。

- TCP：仍填 `0xFFFF`，对端回一整块 `PIECE_DATA`，可忽略掩码。  
- UDP：**首次**向某块要数据时发 `PIECE_REQ`（`sub_mask` 指出需要哪些子包）。此后该块若 500 ms 仍未收齐，**不得**再用 `PIECE_REQ` 作为超时补缺，一律发 `PIECE_NAK` 原因 3（附缺失 `sub_index` 列表）。无论实现上误发了 `PIECE_REQ` 还是按规定发了 `PIECE_NAK`，对同一 `piece_index`、同一对端的**超时补缺次数**合并计数，到 5 即回落中继（见 5.9）。

中心分发模式：只向 `peer_id == 1` 发送。互传模式：向位图显示持有者发送。

### 5.8 `PIECE_DATA`（彭）

**TCP（整块）：**

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 4 | `session_id` |
| 4 | 1 | `file_id` |
| 5 | 1 | `reserved`（0） |
| 6 | 2 | `piece_index` |
| 8 | 2 | `piece_len`（1–16384） |
| 10 | `piece_len` | 块数据 |

**UDP（子包，打洞成功后）：**

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 4 | `session_id` |
| 4 | 1 | `file_id` |
| 5 | 1 | `reserved`（0） |
| 6 | 2 | `piece_index` |
| 8 | 2 | `sub_index`（从 0） |
| 10 | 2 | `sub_count` |
| 12 | 2 | `data_len`（1–1024） |
| 14 | `data_len` | 子包数据 |

须保证整数据报 ≤ 1200 字节（8 字节头 + 14 字节子包头 + 最多 1024 字节数据 = 1046，余量为选项）。**禁止**对打洞用 UDP 套接字调用 `connect()`：该 fd 还要向房间 `37402` 发探测、向多名对端对发，关联单一对端后其余报文会全部丢失。发送一律 `sendto`。

无逐子包确认时，按不少于 **1 ms** 的间隔把 `sub_mask` 内的子包发完；**不得**实现「窗口 4 且等待 ACK」——本协议没有子包 ACK，否则会停住。窗口 4 仅当自行增加了按 `sub_index` 的确认之后才允许。

收齐同一 `piece_index` 的全部子包后，按清单核对该**逻辑分块**摘要，通过才可发 `HAVE` 并标为完成。

UDP 套接字与探测、打洞共用，`recvfrom` 可能来自任意地址。网络线程收到 `PIECE_REQ` / `PIECE_DATA` / `PIECE_NAK` 时，必须将 `sockaddr_in` 的 IPv4 与端口与「已认证表」中某条地址逐字段比较。不匹配则丢弃，不写入子包缓冲，不回 `NAK`，不计入超时次数。`session_id` 相符不得代替地址校验。

已认证表来源：

- 跨网：互达 `PUNCH` 时记下的源地址（打洞成功表）。  
- 本网实验 6：允许把对端**私网** IPv4+UDP 端口预先写入已认证表，**不得**把这一步写成实验 9 的打洞成功。

`PROBE_ACK` 只接受房间服务 `37402`；`PUNCH` 只接受名单中的反射地址或私网地址。

### 5.9 `PIECE_NAK`（彭）

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 4 | `session_id` |
| 4 | 1 | `file_id` |
| 5 | 1 | 原因：1 无此块，2 摘要失败，3 缺子包 |
| 6 | 2 | `piece_index` |
| 8 | 2 | `n_miss`（原因 3 时） |
| 10 | `2 × n_miss` | 缺失的 `sub_index` 列表 |

UDP 超时补缺（归一）：

1. 首次用 `PIECE_REQ` + `sub_mask` 开口。  
2. 此后每满 **500 ms** 该块对应该对端仍未收齐：接收端只发 `PIECE_NAK` 原因 3，并把该对端该块的 `udp_retry` 加 1。发送端只重发列表中的子包。  
3. `udp_retry` 到 **5**（约 2.5 秒）仍未齐：判定该对端 UDP 不可用，刘通知彭改走中继，停止对该对端继续 NAK / 超时 `PIECE_REQ`。  
4. 若实现错误地在超时路径再次发送 `PIECE_REQ`，该次同样计入 `udp_retry`，不得另起一套计数而绕过回落。

`PIECE_NAK` 本身也可丢失，已计入上述 5 次，不再无限循环。  
TCP 上：无此块或摘要失败用原因 1 或 2，`n_miss = 0`。未完成的 TCP `PIECE_REQ` 等待超过 5 秒无应答，视为该 TCP 对端失效（见第 2 节），换其他持有者，不把这次超时算进 UDP 的 `udp_retry`。

### 5.10 `PROBE` / `PROBE_ACK`（刘 / 王）

`PROBE`：

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 2 | `room_id` |
| 2 | 1 | `peer_id`（未分配则 0） |

`PROBE_ACK`：

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 4 | 房间服务看见的源 IPv4 |
| 4 | 2 | 房间服务看见的源 UDP 端口 |

客户端必须用打洞那一个 UDP fd 发送 `PROBE`。王按 `recvfrom` 的源地址填写 `PROBE_ACK`，并写入该 `peer_id` 的反射记录。

每当反射地址由未知变为已知，或端口/地址相对上次有变更，房间服务必须立即向该房**所有已加入且心跳仍在的 TCP 连接**主动推送一条 `PEER_LIST`（`req_id = 0`），不得要求各端轮询 `ADDR_QUERY`。`ADDR_QUERY` 仅作补问。推送前反射仍为 0 的成员，在表中保持 0，收到非 0 后再打洞。

### 5.11 `PUNCH`（刘）

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 4 | `session_id` |
| 4 | 1 | `from_id` |
| 5 | 1 | `to_id` |

同一 UDP fd，向对端反射地址（可同时向其私网地址再发一份）发送。  
**8 秒**内双方都收到来自对端的 `PUNCH`：打洞成功，刘通知彭，此后该 fd 上传 `PIECE_*`。  
超时或强制失败开关：刘通知改连中继 37405，不得把中继成功写成打洞成功。

### 5.12 `RELAY_BIND` / `RELAY_WRAP`（王）

`RELAY_BIND`：`peer_id` 1 字节 + `room_id` 2 字节。中继与房间服务同机，必须核对该 `peer_id` 已在该房间名单中（房间已关闭则核对本局曾经在册的 id）。未在册则回 `ERROR` `0x0012` 并关闭。同一 `peer_id` 再次 `BIND`：关闭旧连接、保留新连接。

`RELAY_WRAP`：

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 1 | `dst_id` |
| 1 | 1 | `src_id` |
| 2 | 2 | `inner_len` |
| 4 | `inner_len` | **完整** v1 报文（含 8 字节头） |

解包（中继与最终接收端）必须同时满足：

- `body_len == 4 + inner_len`
- `inner_len >= 8`（内层至少含一条 v1 头）

任一不成立：丢弃本条，**先按外层 `body_len` 把正文读完**（以免 TCP 流错位），然后关闭该中继连接，回 `ERROR` `0x0010`。不得按错误的 `inner_len` 截取后继续读下一条。

转发前必须再校验：`src_id` **等于**该 TCP 连接在 `RELAY_BIND` 时登记的 `peer_id`。不符则视为冒充：丢弃本条（正文仍按 `body_len` 读完），回 `ERROR` `0x0012`，并关闭该连接。不得按包内 `src_id` 伪造来源去转。`dst_id` 无对应连接则回 `ERROR` `0x000D`，不关闭绑定方（目标未上线可再试）。

中继在上述校验均通过后，向目标连接写出**另一条** `RELAY_WRAP`（`src_id` 用已校验值，内层原样），不得把内层 v1 裸写到中继 TCP 上，以免与 `BIND`/`WRAP` 混读。不解析内层业务。  
陈统计中继证物字节时，只计内层 `PIECE_DATA` 的数据区，不含本封装头。

### 5.13 `ANNOUNCE`（刘）

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 2 | `room_id` |
| 2 | 4 | `session_id` |
| 6 | 4 | 房主私网 IPv4 |
| 10 | 2 | 房主 TCP 互传端口 |
| 12 | 2 | 房主 UDP 端口 |
| 14 | 1 | `nick_len` |
| 15 | `nick_len` | 房主昵称 |

发到 `255.255.255.255:37404`。路由器不转发属预期。不得把通告发到公网。

房间服务已关闭时：新端按通告中的房主私网 IPv4 与 **TCP 互传端口** 直连，在该连接上发 `MANIFEST_REQ` 与 `PIECE_REQ`。房主必须应答。该路径记为类型 4，不经房间分配新的 `peer_id`；房主在 `BITFIELD` 中带自己的 id 即可。新端不得假定还能连上 `37401`。

`HEARTBEAT` / `HEARTBEAT_ACK` 正文可空。间隔 5 s，15 s 无应答视为离线，从本机名单删除，位图保留已校验块。该对心跳用于房间服务 TCP；房间服务关闭后，同样的指令与时限用于各玩家 TCP，以免拔网线且无 FIN 时 `select` 无法发现对端已死。

### 5.14 `MANIFEST_REQ`（彭发，王答）

| 偏移 | 长度 | 名称 |
|------|------|------|
| 0 | 4 | `session_id`（填 0 表示当前房间已缓存的那一份） |

房间已有缓存则回 `MANIFEST` 且 `req_id` 带回；否则 `ERROR` `0x0011`。房主侧若收到该请求，同样回本局清单。

## 7. TCP 读状态机（彭）

每条 TCP 连接独立：

```
状态 S ∈ { READ_HEADER, READ_BODY }
header_got = 0 … 8
body_got   = 0 … body_len
缓冲不超过 8 + 65535
```

1. `READ_HEADER`：`recv` 写入头缓冲剩余部分。不足 8 字节则保持该状态，**不得丢弃已读字节**。满 8 后解析 `body_len`。若为 0，交付空正文并回到 `READ_HEADER`。否则转 `READ_BODY`。  
2. `READ_BODY`：累计至 `body_len`。一次 `recv` 若多余，留给下一条头部。  
3. 不得调用「恰好读 8 字节」且在短路时放弃已读前缀。

实验 1 用较小 `recv` 缓冲演示本状态机；抓包须能指出 `htons`/`ntohs` 作用在 `magic`、`req_id`、`body_len` 及正文中的多字节字段。

## 8. 网络线程须同时等待的描述符（彭）

`select`（或等价）至少包括：

1. 与房间服务的 TCP  
2. 本机 TCP 互传 `listen`  
3. 已 `accept` / `connect` 的各玩家 TCP  
4. 打洞用 UDP（与探测同一 fd）  
5. 通告 UDP（若本进程负责通告）  
6. 中继 TCP（走中继时）  
7. 唤醒用套接字（或 POSIX 下 `pipe` 读端）。Windows 上此项必须是 `SOCKET`，见第 2 节。  

界面线程禁止在 1–6 上读写。用户「请求证物 / 切换节点 / 开始打洞」时向唤醒写端写入 1 字节。  
房间表、位图、路径类型：界面与网络两线程之间加互斥量。

Linux 上 `select` 的第一参数为最大描述符编号加一；Windows 上该参数被忽略。正在进行的非阻塞 `connect` 把该套接字放入写集合，1.5 秒截止；到期从集合中拿掉并改走打洞，不得让 `select` 无限等这次握手。

玩家 TCP 已接通后：套接字开 `SO_KEEPALIVE`；该连接上未完成请求 5 秒无应答，或（房间服务已关闭时）15 秒无 `HEARTBEAT_ACK`，从读集合移除并换源。拔网线且对端未发 FIN 时，不得让 `select` 永远认为该连接仍可读可写地活着。

## 10. 界面状态（刘）

界面可持有的字段（均来自报文或本机判断，无种子）：

- 局号：`session_id` 十六进制  
- 自己的昵称、`peer_id`  
- 三人昵称与地址（不展示反射地址以外的探测细节亦可）  
- 三个文件的整文件摘要（可只显示前 8 个十六进制字符，完整值可展开）  
- 各文件块进度（来自位图）  
- 当前缺失块的来源昵称  
- 路径类型（第 9 节）  
- 房间服务是否在线  
- 唯一持有者离线时的等待提示（不得假装已完成）

界面状态：`空闲` → `在房` → `第一章` → `章间问答` → `第二章` → `三项择一` → `结束`。  
章节解锁只根据**本机已校验文件**，不根据房间广播「可以进入下一章」。

开局残页是剧情切片，数量与 16 KiB 逻辑分块无关，不得用残页张数当块号。

## 11. 打洞与中继衔接（刘客户端，王中继，彭传块）

1. 进程启动：创建 UDP fd，`bind(INADDR_ANY, 0)`，保存该 fd 至退出。**不要**对该 fd 调用 `connect`。  
2. TCP 加入房间，收到 `JOIN_OK`（含自己的 `peer_id`）之后，再用同一 UDP fd 向 `房间:37402` 发 `PROBE`，正文必须带已分配的 `peer_id`（禁止长期用 0）。  
3. 王把反射地址写入名单，并立即向全房推送 `PEER_LIST`。反射仍为 0 时刘不得对发。`ADDR_QUERY` 仅作补问。  
4. 刘用同一 fd 向非 0 反射地址发 `PUNCH`（可同时向名单中的私网 UDP 端口再发一份）。  
5. 成功：将该 `recvfrom` 源地址写入已认证表。若尚未交换位图则补发 `BITFIELD`。彭在该 fd 上 `sendto` `PIECE_*`。首次 `PIECE_REQ`，其后超时只走 `PIECE_NAK` 原因 3；`udp_retry` 到 5 则刘通知彭将该对端改为中继。  
6. 打洞 8 秒未互达、强制失败开关、或第 5 步 UDP 失效：各端 TCP 连接 `中继:37405`，`RELAY_BIND`，此后 `PIECE_*` 放进 `RELAY_WRAP`。  
7. 彭不负责判定 NAT 类型；刘在实验 9 记录锥型 / 对称型（或注明强制失败开关）。

## 13. 占位与升版

第 1 周彭可用 `session_id = 1`、单文件 16384 字节全零、摘要按实算，做实验 1。第 2 周起必须改用陈的真实清单与分块。晚进房用 `MANIFEST_REQ` 或等待 `JOIN_OK` 后的缓存 `MANIFEST`，不得假定开局广播自己一定能收到。

本约定缺陷以 `ver = 2` 修订。v1 与 v2 不得混连。确认签字前的字段增补（`sub_mask`、`MANIFEST_REQ`、位图中的 `peer_id`）仍记为 v1，已按本节实现者不必升版。
